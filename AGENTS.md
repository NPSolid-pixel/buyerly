# Инструкции для AI-агентов (Buyerly)

## 🖥 Системное окружение
- **ОС**: NixOS (Linux).
- **Пакеты и запуск**: Для запуска компиляторов и утилит использовать `nix-shell` (например `nix-shell -p ...`).

## 🌿 Git и работа с ветками (СТРОГИЕ ПРАВИЛА)

1. **Никаких цепочек веток (No branch stacking):**
   * Каждая новая задача (Issue) создаётся **СТРОГО от чистого и обновлённого `main`**:
     ```bash
     git checkout main
     git pull origin main
     git checkout -b <type>/issue-<N>-<short-name>
     ```
   * **Категорически запрещено** создавать ветки поверх других незамёрдженных фиче-веток.

2. **Изоляция изменений:**
   * 1 ветка = 1 Issue / 1 конкретная задача.
   * Никаких правок других компонентов, документов или параллельных задач внутри рабочей ветки.

3. **Хотфиксы и документация:**
   * Любые обновления юридических документов, политик, инструкций или мелкие фиксы оформляются **отдельной изолированной веткой** от `main` (например `docs/update-privacy-policy` или `fix/...`), а не поверх открытых задач.

4. **Проверка перед коммитом и PR:**
   * Перед созданием PR или слиянием обязательно проверить:
     ```bash
     git log --oneline main..HEAD
     git diff --stat main..HEAD
     ```
   * Убедиться, что ветка содержит **только свои целевые коммиты**.

5. **Стандарт коммитов:**
   * Использовать Conventional Commits (`feat: ...`, `fix: ...`, `perf: ...`, `docs: ...`, `test: ...`, `refactor: ...`).
   * В описании коммита или PR всегда указывать `Closes #N` / `Fixes #N`.

6. **Деплой на Production:**
   * `main` автоматически деплоится на VPS через GitHub Actions (`.github/workflows/deploy.yml`).
