# Buyerly Information Architecture

Основной язык продукта — русский. Английский допускается только для официальных имён платформ и общепринятых сокращений метрик; весь пользовательский текст проходит через translation layer.

## Jobs-to-be-done

| Задача пользователя | Раздел | Результат |
| --- | --- | --- |
| Увидеть, что требует внимания | Сегодня | Приоритеты, состояние и быстрые действия |
| Понять причины результата | Эффективность | Метрики, сравнение и детализация |
| Настроить повторяемое действие | Автоматизации | Правила, лимиты и назначение кабинетов |
| Проверить, что произошло | История действий | Аудит действий и системных событий |
| Подключить источник и управлять доступом | Подключения | Facebook-профили, Business Manager и кабинеты |
| Изменить параметры продукта | Настройки | Пользователь, workspace и автоматизация |

## Навигация

Единый порядок на desktop и mobile:

1. Сегодня
2. Эффективность
3. Автоматизации
4. История действий
5. Подключения
6. Настройки

Рекламные кабинеты остаются рабочим представлением внутри «Подключений» и доступны из списка групп кабинетов.

## Канонические и совместимые URL

| Раздел | Канонический URL | Совместимые aliases |
| --- | --- | --- |
| Сегодня | `/today` | `/`, `/home`, `/main`, `/dashboard` |
| Эффективность | `/efficiency` | `/summary` |
| Автоматизации | `/automations` | `/rules` |
| История действий | `/action-history` | `/logs` |
| Подключения | `/connections` | `/facebook-accounts`, `/fb-accounts`, `/fb_accounts`, `/add-accounts`, `/add` |
| Настройки | `/settings` | — |

Все маршруты также поддерживаются с префиксом `/{workspace_slug}`. Старые ссылки восстанавливают соответствующий раздел без потери workspace и фильтра группы.

## Терминология

| Канонический термин | Значение |
| --- | --- |
| Facebook-профиль | Пользователь Meta, через которого создано подключение |
| Business Manager | Бизнес-портфель Meta; официальное имя не переводится |
| рекламный кабинет | Meta Ad Account |
| группа кабинетов | Пользовательская коллекция рекламных кабинетов в Buyerly |
| кампания | Meta campaign |
| группа объявлений | Meta ad set |
| объявление | Meta ad |
| автоматизация | Правило, которое проверяет условия и выполняет действие |
| история действий | Аудит пользовательских и системных событий |

Нельзя смешивать `FB Аккаунты`, `Facebook Профили`, `BM`, `Правила` и `Логи` как названия верхнего уровня. Допустимы CPM, CPC, CTR и CPL, если при первом использовании рядом раскрыто значение.

## Роли и видимость

| Возможность | Admin | Buyer | Viewer |
| --- | --- | --- | --- |
| Сегодня и Эффективность | Все workspace-данные | Назначенные кабинеты | Только чтение доступных данных |
| Автоматизации | Создание, изменение, назначение | Управление разрешёнными автоматизациями | Только чтение |
| История действий | Полный аудит workspace | События доступных кабинетов | Только чтение |
| Подключения | Подключение, отзыв, импорт | Просмотр и разрешённое переподключение | Только чтение |
| Настройки | Workspace, роли, системные параметры | Личный профиль | Личный профиль |

Информационная архитектура не заменяет backend RBAC: недоступные мутации должны быть скрыты в UI и отклонены API.

## Локализация

- `ru` — основной и резервный locale.
- Тексты навигации и сущностей берутся из `window.BuyerlyI18n`.
- Новая пользовательская строка не должна появляться одновременно на русском и английском.
- Форматы дат, времени, чисел и валют используют locale пользователя; имена API-полей в интерфейс не выводятся.
- Email и username остаются техническими идентификаторами и не переводятся.

## Длинные списки

Списки подключений, кабинетов, автоматизаций и событий используют один паттерн:

1. Поиск по имени и идентификатору.
2. Фильтры по статусу, группе и доступности, когда набор превышает один экран.
3. Видимый счётчик найденного.
4. Отдельные empty states для «данных нет» и «ничего не найдено».
5. Сохранённые виды для аналитических таблиц и повторяемых фильтров.

## Definition of Done

- Desktop и mobile показывают одинаковые шесть разделов в одном порядке.
- Канонические и legacy URL открывают правильный раздел внутри workspace.
- Пользовательские названия соответствуют словарю и основному русскому locale.
- Подключения можно искать без запроса к Meta API.
- Viewer не получает визуального обещания недоступной мутации.
- Контракты IA и маршрутов проходят в GitHub Actions.
