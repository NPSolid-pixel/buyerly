# BL-106: рабочее пространство «История действий»

Дата: 2026-08-29
ClickUp: `86eyrx9c6`
Ветка: `feat/bl-106-action-history-workspace`
Статус: реализовано и Browser-QA проверено; ожидает GitHub Actions

## Цель

Завершить workspace-scoped историю действий как рабочий экран: пользователь
должен быстро найти событие, понять результат и причину, открыть полные детали
и безопасно выполнить undo либо увидеть точное объяснение, почему оно
недоступно.

## Реализация

1. Сохранить единственным источником данных `GET /api/audit-events` и строгий
   фильтр по активному workspace; расширить поиск техническими идентификаторами
   и нормализовать пагинацию без раскрытия событий другого workspace.
2. Довести desktop-таблицу и mobile-ленту до общего контракта: статусы,
   человекочитаемые события и инициаторы, длинные имена/ID, доступность undo и
   раскрытие деталей.
3. Сделать фильтры рабочими для поиска, категории, статуса, кабинета и периода;
   добавить сброс и отдельное filtered-empty состояние.
4. Добавить устойчивые loading, empty и error/retry состояния, защиту от гонок
   запросов при смене фильтра или workspace и понятный live-region статус.
5. Сделать детали и undo доступными с клавиатуры, добавить подтверждение,
   локальную ошибку undo, возврат фокуса и mobile bottom-sheet без
   горизонтального overflow.
6. Обновить frontend/API контрактные тесты и changelog.

## Проверка

- Локально не запускать `pytest`, `unittest` и другие test runners согласно
  `AGENTS.md`.
- Выполнить разрешённые статические проверки JavaScript, Python, whitespace и
  целевого diff.
- Полный набор контрактных, unit и integration тестов выполнить только в
  GitHub Actions.
- Проверить desktop/mobile layout и отсутствие document-level horizontal
  overflow разрешённым browser/static способом, если окружение позволяет.

## Definition of Done

- Поиск и каждый фильтр меняют server-backed выдачу и могут быть полностью
  сброшены.
- Loading, исходный empty, filtered empty и error/retry визуально и семантически
  различимы.
- Таблица и mobile-лента открывают одинаковые детали; длинные ID и тексты не
  расширяют документ.
- Undo доступен только при `can_undo=true`; для остальных событий показана
  серверная причина, а ошибка не закрывает детали.
- Быстрые запросы и смена workspace не могут отобразить устаревшие события.
- API по-прежнему выдаёт и отменяет события только активного workspace.
- Отдельный PR содержит ClickUp ID, описание и проверки; CI зелёный, merge не
  выполняется без явного подтверждения пользователя.

## Browser QA

- На `1440×900`, `768×900` и `390×844` подтверждено
  `documentElement.scrollWidth === documentElement.clientWidth`; широкая
  desktop-таблица прокручивается только внутри своего viewport.
- На `390px` desktop-таблица скрыта, mobile-карточки имеют собственные доступные
  button semantics и не расширяются от длинных названий, сообщений и ID.
- Details dialog сохраняет ширину viewport, JSON и operation ID прокручиваются
  или переносятся локально; на mobile диалог становится bottom sheet.
- Проверены filtered-empty и сброс фильтров, открытие деталей, focus trap,
  закрытие по Escape и возврат фокуса к исходной строке/карточке.
- В браузере не зафиксировано console error/warning.
