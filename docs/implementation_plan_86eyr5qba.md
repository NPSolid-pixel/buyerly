# План реализации 86eyr5qba

## Цель

Сделать `core/config.py`, `.env.example` и инструкции запуска единым проверяемым
контрактом без устаревших или вымышленных способов конфигурации.

## Контракт

- Каждое runtime-поле `Settings` присутствует в `.env.example` ровно один раз.
- Единственная compose-only переменная примера — `POSTGRES_PASSWORD`.
- Production-документация разделяет обязательные базовые, Meta, опциональные и
  автоматически управляемые параметры.
- Resend REST API остаётся единственным почтовым transport; неиспользуемые SMTP
  настройки не рекламируются и не входят в runtime Settings.
- Dev fallback не утверждает, что секретный OTP или тело письма пишутся в лог.

## Проверка готовности

- AST-контракт сравнивает поля `Settings` с ключами `.env.example`.
- Документационные тесты фиксируют production-набор и безопасное описание почты.
- Полный GitHub Actions pipeline проходит до слияния и production deploy.
