# План реализации 86eyr5z4t

## Цель

Не принимать произвольные байты под видом изображения, не терять загруженные
файлы между релизами и не накапливать логотипы, которые больше не используются.

## Контракт

- Сервер доверяет декодированному формату, а не только имени или MIME файла.
- Разрешены однокадровые PNG, JPEG и WEBP до 5 МБ и 20 млн исходных пикселей.
- Файл уменьшается до 2048 px, очищается от метаданных и заново кодируется перед
  атомарной записью.
- Локальный логотип может привязать только загрузивший его пользователь.
- Замена или удаление ссылки удаляет файл лишь после commit и только если на него
  больше не ссылается другой воркспейс.
- Непривязанные логотипы получают grace period 24 часа, после чего очищаются.
- Production API и Nginx используют общий именованный volume; web имеет к нему
  только read-only доступ.

## Проверка готовности

- Интеграционные тесты покрывают ложный формат, несовпадение расширения,
  каноническую запись, ownership, замену и очистку orphan-файлов.
- Контракт deploy проверяет постоянный volume, legacy-перенос и Nginx `nosniff`.
- Полный GitHub Actions pipeline проходит до слияния и production deploy.
