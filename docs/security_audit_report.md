## 🎯 1. Цели и методология аудита

Аудит проводился по принципам **адверсариального анализа (Adversarial Security Review)** и моделирования угроз с точки зрения внешнего злоумышленника, недобросовестного арендатора (tenant escalation), неавторизованного пользователя и сбоев внешних провайдеров (Meta API / Telegram).

Аудитом были охвачены:
1. **Финансовая логика и правила остановки рекламных кампаний** (защита от слива бюджета).
2. **Мульти-арендная изоляция (Multi-Tenant Workspace Security)** (защита данных между организациями и баерами).
3. **Аутентификация, сессии и криптография** (защита учетных записей, OTP, токены доступа).
4. **Отказоустойчивость, защита от DoS и ReDoS** (устойчивость под нагрузкой и защита от исчерпания памяти/CPU).

## ⚙️ 3. Архитектурная отказоустойчивость и надежность Meta API

1. **Concurrency Control**:
   - Воркер мониторинга защищен семафорами `max_concurrent_accounts` и `max_concurrent_actions`.
   - Применение действий к адсетам сериализуется через транзакционные блокировки `SELECT ... FOR UPDATE` в `RuleExecutionState`.
2. **Meta API Quota Protection**:
   - Автоматический Exponential Backoff + Jitter при HTTP 429 / 5xx.
   - Адаптивное замедление фонового опроса при расходе квоты Meta 60% (Soft Limit) и временная приостановка некритичных запросов при 80% (Hard Limit).
3. **Crash Recovery & Reconciliation**:
   - Поддержка автоматического восстановления статусов (`reconciled_after_restart`) после внезапной перезагрузки сервера.
   - Heartbeat-мониторинг активности воркера (`/tmp/buyerly-worker-heartbeat`).
