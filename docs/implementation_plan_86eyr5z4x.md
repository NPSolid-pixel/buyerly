# План реализации 86eyr5z4x

## Цель

Привязать уникальность названия группы кабинетов к воркспейсу, а не к создавшему
её пользователю, и закрыть гонку параллельных запросов.

## Контракт

- В одном воркспейсе `Group`, `group` и ` group ` считаются одним названием.
- Одинаковое название разрешено в разных воркспейсах, даже если владелец один.
- PostgreSQL functional unique index является окончательным арбитром гонки.
- Проигравший create/update получает HTTP 409; транзакция откатывается целиком.
- Legacy-группы получают workspace по единственному workspace участников либо по
  подтверждённому active workspace владельца.
- Существующие дубли не удаляются: они получают минимальный детерминированный
  суффикс `(2)`, `(3)` с сохранением membership.
- Неоднозначные legacy-группы без workspace скрываются из tenant API.

## Проверка готовности

- Интеграционные тесты покрывают параллельное создание, регистр и одинаковое имя
  в двух воркспейсах.
- Миграционный тест подтверждает backfill, сохранение дублей и новый индекс.
- Полный GitHub Actions pipeline проходит до слияния и production deploy.
