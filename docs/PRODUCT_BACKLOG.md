# Product backlog Buyerly

Этот файл — единый реестр продуктовых изменений Buyerly. Он хранится вместе с кодом, отображается на GitHub и изменяется тем же отдельным коммитом, которым выпускается задача.

## Как закрывается задача

Задача считается выполненной только после всех проверок:

- [ ] реализация закончена;
- [ ] автоматические тесты пройдены;
- [ ] интерфейс проверен на desktop и mobile;
- [ ] изменение отправлено отдельным коммитом в `main`;
- [ ] production успешно обновлён;
- [ ] API и затронутый пользовательский сценарий проверены на production;
- [ ] документация и этот backlog обновлены;
- [ ] результат принят владельцем продукта.

Для каждой выполненной задачи рядом с чекбоксом добавляются номер GitHub Issue, commit SHA и дата production-проверки. История действий и исходные требования не удаляются.

## Зафиксированные продуктовые решения

- Цветовая палитра, логотипы и визуальный характер Buyerly сохраняются.
- Компоновку страниц, навигацию, размеры блоков, плотность данных и структуру таблиц можно менять.
- Интерфейс должен позволять анализировать Meta Ads без постоянного открытия рекламных кабинетов в антидетект-браузере.
- Лиды, регистрации и покупки — независимые этапы воронки. Их нельзя складывать в общий показатель «Результаты».
- Любая цифра должна иметь определение, формулу, источник, период, часовой пояс и время последнего обновления.
- Успешное действие автоправила сразу считается выполненным. Подтверждение не требуется; обратимые действия можно безопасно отменять.
- Система показывает столько метрик Meta, сколько технически доступно текущим разрешениям и типу рекламы. Неподдерживаемые или отсутствующие значения отображаются как `—`, а не как ноль.
- Состав, порядок, ширина и видимость метрик сохраняются для пользователя. Для отдельного кабинета можно создать собственное представление, перекрывающее пользовательское по умолчанию.
